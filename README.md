# pqdif

A native Python reader and writer for IEEE Power Quality Data Interchange Format
(PQDIF). MIT licensed. Python 3.11+. No .NET runtime or mandatory NumPy dependency.

**Status: 0.1.0a1, an initial alpha.** Full IEEE 1159.3-2025 compatibility is the
target; conformance is not yet established. See the [support matrix](docs/compatibility.md)
for verified behavior and limits. This project is independent of IEEE and GPA.

## Install

From a checkout:

```sh
python -m pip install .
python -m pip install '.[numpy]'  # optional array integration
```

The distribution and import are both `pqdif`. No PyPI release has been published
by this project. For a supplied wheel, use `python -m pip install /path/to/pqdif-*.whl`.

## Create, write and read

```python
from datetime import datetime, timezone
from pqdif import Channel, Observation, PqdifFile, PhysicalType, Series, read, write

voltage = Series([0.25, -1.5, 3.75], units=6, physical_type=PhysicalType.REAL8)
event = Observation(
    "Voltage waveform",
    datetime(2026, 1, 2, tzinfo=timezone.utc),
    [Channel("Va", [voltage], phase=1, quantity=1)],
    source_name="Example meter",
)
file = PqdifFile([event], compressed=True, filename="waveform.pqd")
write(file, "waveform.pqd")

result = read("waveform.pqd")
series = result.observations[0].channels[0].series[0]
assert series.values == (0.25, -1.5, 3.75)
samples = series.to_numpy()  # optional NumPy; read-only, zero-copy here
```

`units=6`, `phase=1`, and `quantity=1` are the PQDIF codes for volts, phase AN,
and voltage. The [registry](docs/api.md#identifiers) exposes all pinned identifier
names and codes. Generic series also represent logs, phasors, spectra, histograms,
and vendor-defined quantities; metadata determines their meaning.

## Read, edit and preserve extensions

```python
from pqdif import read, write

file = read("input.pqd")
file.observations[0].name = "Reviewed event"
file.observations[0].channels[0].name = "Voltage A"
file.compressed = True
write(file, "reviewed.pqd")
```

Known properties are live views of physical trees. Unknown tags, unknown records,
ordered/duplicate extension elements, exact numeric bytes, and nested vendor
metadata stay with the file. Semantic equivalence is the contract; padding, links,
compression bytes and checksums may change. Unknown *physical encodings* have
additional [relocation restrictions](docs/compatibility.md#preservation).

## Low-level API

```python
from pqdif.codec import decode_collection, encode_collection
from pqdif.physical import read_records, write_records

records = read_records("input.pqd")
for record in records:
    print(record.type_tag, record.body)
write_records(records, "rewritten.pqd")
```

`Scalar`, `Vector`, `Collection`, `OpaqueElement`, `Record` and `Timestamp`
retain the physical representation. The logical layer binds active sources and
settings to observations without replacing that representation.

## Validation and limits

```python
from pqdif import Limits, read

file = read("input.pqd", limits=Limits(
    max_file_bytes=32 * 1024 * 1024,
    max_record_bytes=8 * 1024 * 1024,
    max_expanded_values=1_000_000,
))
```

Sizes, counts, nesting, links, allocation overlap, checksums, compressed expansion,
logical indexes and shared-series cycles are checked. Low-level readers validate
physical safety; high-level readers/writers also validate supported logical rules.
See [API contracts](docs/api.md) for `validate=False`, checksum policy and errors.

## Development

```sh
python -m pip install -e '.[dev]'
python -m pytest
python -m ruff check src tests tools examples
python -m ruff format --check src tests tools examples
python -m mypy src/pqdif
python -m build
```

Normal tests always read committed fixtures independently generated by GPA's
Gemstone library. A live oracle also tests both read/write directions. Its .NET SDK
and NuGet dependencies are test tooling only. See [development instructions](docs/development.md)
for required-oracle execution and fixture regeneration.
